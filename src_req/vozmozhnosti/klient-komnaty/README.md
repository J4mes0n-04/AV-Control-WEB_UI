# klient-komnaty — веб-клиент управления комнатой

**Capability (OpenSpec):** `klient-komnaty`  
**Продукт:** управление помещением в браузере и в клиент-оболочке (режим киоска на панели).  
**Основные пользователи:** End User, Room Operator.

## Назначение папки

Здесь описывается **опыт конечного пользователя комнаты**: загрузка и отображение проекта, запуск сценария в одно–два действия, понятные ошибки без инженерных терминов, аутентификация на клиенте, киоск, нативные типовые состояния (потеря связи, заглушка, по расписанию), согласованность нескольких панелей одной комнаты.

Модель «панель → сервер → оборудование» важна как контекст, но **реализация связи и команд** — вне этого репозитория. Здесь только то, что пользователь видит и нажимает.

## Что здесь будет храниться

| Файл (план) | Содержание |
|-------------|------------|
| `naznachenie.md` | Роль клиента комнаты, offline-first с точки зрения экрана, киоск vs браузер |
| `povedenie.md` | User flows: вход в комнату, виджеты, запуск сценария, состояния UI, тексты ошибок (FR-ROOM-*, UX из Scope) |
| `granicy.md` | Исключения: прямое управление железом из клиента (OOS-06), legacy «толстый клиент» (OOS-07); P0/P1 по клиенту |

**Источники пакета:** PRD M-ROOM, «Logic & User Flows — AV Control», Use Case для оператора комнаты, Scope §1.2 и блок P0 «Клиент управления комнатой», PSD — рендеринг/виджеты на уровне поведения экрана.

## Чего здесь не должно быть

- Программирование сценариев на сервере (M-AUT) — только кнопки/результат на клиенте.
- Настройка тегов и связей (M-VAR) — только отображение значений на элементах UI.
- Драйверы и протоколы — только экранные индикаторы «нет связи», «устройство недоступно».

## Связь с OpenSpec

Capability `klient-komnaty` — отдельная spec при изменениях клиента комнаты. Сквозные темы (единый стиль ошибок, вход) могут ссылаться на `obshchiy-interfejs`.
