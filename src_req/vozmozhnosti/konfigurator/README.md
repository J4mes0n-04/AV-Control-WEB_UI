# konfigurator — веб-конфигуратор проектов

**Capability (OpenSpec):** `konfigurator`  
**Продукт:** конфигуратор серверного и клиентского проектов через браузер (замена Studio).  
**Основной пользователь:** Integrator Engineer (AV-инженер интегратора).

## Назначение папки

Здесь собирается всё, что инженер **видит и делает в веб-интерфейсе** при настройке проекта: структура проекта, сборка, импорт/экспорт, привязка элементов интерфейса, ограниченная кастомизация экрана (текст, иконки, цвета, видимость, порядок блоков), тема клиента, работа с несколькими проектами в UI.

Папка описывает **WEB UI/UX конфигуратора**, а не формат файла проекта на диске, не сервер сборки и не runtime исполнения на контроллере.

## Что здесь будет храниться

| Файл (план) | Содержание |
|-------------|------------|
| `naznachenie.md` | Зачем веб-конфигуратор, отличие от «настройки контроллера», границы MVP vs P1 (кастомизация, шаблоны) |
| `povedenie.md` | Пошаговые сценарии на экране: создание/открытие проекта, режимы сборки, автоподключение в UI, сообщения об ошибках, импорт/экспорт с точки зрения пользователя |
| `granicy.md` | Что не входит (глубокая кастомизация уровня i3 Pro — OOS-12), приоритеты P0/P1 по FR-PRJ-* только для UI |

**Источники пакета:** PRD M-PRJ (`FR-PRJ-*`), Use Case и Logic & User Flows для инженера, Scope §1.1, PSD — только фрагменты про отображение и редактор.

## Чего здесь не должно быть

- SDK драйверов, манифест драйвера, физические интерфейсы (M-DRV) — кроме экранов «установить/обновить драйвер» в конфигураторе, если они есть в UI.
- Движок Expression Evaluator и JS-расширение как исполнение — только UI настройки правил/сценариев, если пользователь это редактирует здесь.
- Полная IA & Data Schema — только то, как сущности **показаны** в редакторе.

## Связь с OpenSpec

При первом изменении по конфигуратору из этой папки формируют change, например `web-konfigurator-mvp`, с delta spec в `openspec/changes/.../specs/konfigurator/spec.md`.
