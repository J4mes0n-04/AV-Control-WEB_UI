# obshchiy-interfejs — сквозной WEB UI/UX

**Capability (OpenSpec):** `obshchiy-interfejs`  
**Продукт:** общие правила интерфейса для всех трёх веб-поверхностей (конфигуратор, клиент комнаты, admin).  
**Пользователи:** все роли; в первую очередь согласование для PDE и QSRE.

## Назначение папки

Здесь собирается то, что **повторяется на всех экранах** и не принадлежит одной capability: вход и сессия с точки зрения UI, отображение прав (что скрыто/заблокировано для роли), единые паттерны ошибок и успеха, offline и «нет связи», заглушки и empty states, базовая доступность и отзывчивость интерфейса (NFR-PERF-01 как ощущение пользователя), согласованность терминов на экране.

Отдельная папка нужна, чтобы не копировать одни и те же правила в `konfigurator`, `klient-komnaty` и `admin-kontroller`, а ссылаться на один источник при написании spec.

## Что здесь будет храниться

| Файл (план) | Содержание |
|-------------|------------|
| `naznachenie.md` | Принципы UX продукта, связь со стратегией (Time to Working Room, типовой сценарий без JS — на уровне **видимого** UI) |
| `povedenie.md` | Требования к текстам сообщений (Scope §4: UX / Data Schema), форматы ошибок FR-ROOM-06, аутентификация «на экране», TLS только как индикатор «защищённое соединение» при необходимости |
| `granicy.md` | Что не унифицируем (специфика киоска vs desktop); что остаётся локальным в capability-папках |

**Источники пакета:** PRD NFR (PERF, REL, UX-ориентиры), Scope карта владения «тексты пользовательских сообщений», Logic & User Flows — общие ветки ошибок.

## Чего здесь не должно быть

- Полная матрица RBAC и аудит (M-SEC) — только **отражение** прав в UI.
- Детальная тема/дизайн-система каждого приложения — общие токены и правила; уникальные экраны — в capability-папках.
- Контент, относящийся только к одной поверхности (например, только виджет «громкость» в комнате) — в `klient-komnaty`.

## Связь с OpenSpec

Capability `obshchiy-interfejs` может быть базовой spec, на которую ссылаются delta других changes («MODIFIED» или перекрёстные сценарии). При конфликте приоритет: сначала согласовать `obshchiy-interfejs`, затем детали в `konfigurator` / `klient-komnaty` / `admin-kontroller`.
