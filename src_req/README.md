# Исходные требования AV Control WEB UI/UX

Эта папка хранит исходное описание продукта **только для веб-интерфейса и пользовательского опыта**. OpenSpec не читает `src_req` автоматически. Согласованные формулировки позже переносят в артефакты изменения (`proposal.md`, `specs/**/spec.md`, `design.md`, `tasks.md`) после `openspec init` в корне проекта AV Control.

## Граница репозитория

В этом репозитории разрабатывают **WEB UI/UX**: экраны, сценарии на экране, тексты, состояния интерфейса, доступность действий для роли. Серверная логика, драйверы, протоколы, лицензирование на уровне контроллера и контракты API сюда не входят, кроме того, как это **отображается или настраивается через веб**.

## Структура

```text
src_req/
├── README.md                 этот файл
├── openspec-config.yaml      черновик openspec/config.yaml продукта
├── produkt/                  общий контекст (6 md-заготовок, см. produkt/README.md)
└── vozmozhnosti/             веб-поверхности как будущие capabilities OpenSpec
    ├── konfigurator/
    ├── klient-komnaty/
    ├── admin-kontroller/
    └── obshchiy-interfejs/
```

Источник для наполнения: `Консолидированный пакет/` (PRD, PSD, Use Case, Logic & User Flows, IA, Scope). В `src_req` попадают **выдержки про экран и опыт**, а не полные копии документов.

## Язык

Команда русскоязычная. По-русски пишутся файлы в `src_req/`, артефакты OpenSpec и комментарии в коде. Английский — только служебные заголовки и слова OpenSpec (`SHALL`, `MUST`, `WHEN`, `THEN`), пути, код и устойчивые термины `UI`, `API`, `HTTP`. Подробности — в `openspec-config.yaml`.

## Связь с OpenSpec

Каждая папка в `vozmozhnosti/` соответствует одной **capability** в `openspec/specs/<имя>/spec.md`. Имена папок — латиница для путей; смысл описан в README каждой папки.
