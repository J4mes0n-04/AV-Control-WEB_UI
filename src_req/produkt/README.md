# produkt — общий контекст WEB UI/UX

## Назначение папки

Здесь хранится то, что относится ко **всему веб-продукту сразу**, а не к одной экранной поверхности. Это рамка для PDE, ASE, QSRE и агента: кто пользователи, зачем три веб-приложения, что сознательно **не** делаем в этом репозитории.

Папка не заменяет OpenSpec. Это черновик и справочник до появления изменений в `openspec/changes/`.

## Файлы в папке

| Файл | Содержание | Источник пакета |
|------|------------|-----------------|
| `obzor.md` | Цели WEB UI/UX, North Star на языке экрана, OBJ | PRD §1 |
| `persony-i-prava-ui.md` | Персоны и что видно/доступно в вебе | PRD §2 |
| `tri-veb-prilozheniya.md` | Конфигуратор, клиент комнаты, admin — границы и аудитория | PRD M-PRJ, M-ROOM, M-ADM |
| `granicy.md` | Граница репозитория + OOS для UI | Scope §2 |
| `prioritety.md` | P0/P1/P2 только для экранных возможностей | Scope §0.5, FR «веб» |
| `nfr-ekrana.md` | NFR, проверяемые через UI | PRD NFR, FR-ROOM-06 |

Сейчас файлы — **заготовки** с разделами `TODO`; наполнение — выдержками из `Консолидированный пакет/`.

## Чего здесь не должно быть

- Пошаговых сценариев одного экрана — `vozmozhnosti/*/povedenie.md`.
- Полного PRD, PSD или Scope целиком.
- Серверных контрактов API и форматов проекта — только отсылка «на экране…».

## Связь с OpenSpec

| Файлы | Куда в change |
|-------|----------------|
| `obzor.md`, `granicy.md` | proposal → Why, Impact |
| `tri-veb-prilozheniya.md`, `persony-i-prava-ui.md` | proposal → Capabilities, Impact |
| `prioritety.md` | выбор capability и порядка changes |
| `nfr-ekrana.md` | spec → сценарии приёмки UI |
